# Requirements Document

## Introduction

This document specifies the requirements for the Owner Dashboard & Mosque Management (List) feature in the eMasjid platform. This feature enables platform owners (super-admins) to monitor platform statistics, view all registered mosques, and manage mosque verification requests. The owner needs visibility into the total number of mosques, congregation members across the platform, and platform fee revenue, as well as the ability to view mosque lists filtered by their verification status.

## Glossary

- **Owner**: A user with the super-admin role who manages the entire eMasjid platform
- **Platform**: The eMasjid system that hosts multiple mosques
- **Mosque**: A registered masjid entity on the platform with status: pending, active, suspended, or rejected
- **Congregation**: Users who have joined mosques as jamaah (members)
- **Platform_Fee**: Revenue generated by the platform from donation transactions
- **Dashboard_Service**: The backend service that aggregates platform-wide statistics
- **Mosque_Service**: The backend service that handles mosque listing operations
- **Dashboard_Controller**: The backend controller handling owner dashboard requests
- **Mosque_Controller**: The backend controller handling mosque management requests
- **DataTable**: A frontend component that displays tabular data with pagination, filtering, and sorting

## Requirements

### Requirement 1: Owner Authentication and Access Control

**User Story:** As a platform owner, I want to access the owner dashboard, so that I can monitor and manage the entire eMasjid platform.

#### Acceptance Criteria

1. THE Owner SHALL be authenticated via the web authentication guard
2. WHEN an unauthenticated user attempts to access owner routes, THE Platform SHALL redirect the user to the login page
3. WHEN an authenticated user without super-admin role attempts to access owner routes, THE Platform SHALL return a 403 Forbidden response
4. THE Platform SHALL use the EnsureOwnerAccess middleware to verify super-admin role before granting access to owner routes

### Requirement 2: Platform Statistics Dashboard

**User Story:** As a platform owner, I want to view platform-wide statistics, so that I can monitor the overall health and growth of the eMasjid platform.

#### Acceptance Criteria

1. WHEN the owner accesses the dashboard, THE Dashboard_Service SHALL calculate the total number of mosques with status 'active'
2. WHEN the owner accesses the dashboard, THE Dashboard_Service SHALL calculate the total number of mosques with status 'pending'
3. WHEN the owner accesses the dashboard, THE Dashboard_Service SHALL calculate the total number of mosques with status 'suspended'
4. WHEN the owner accesses the dashboard, THE Dashboard_Service SHALL calculate the total number of congregation members across all active mosques
5. WHEN the owner accesses the dashboard, THE Dashboard_Service SHALL calculate the total platform fee revenue from confirmed donations
6. THE Dashboard_Controller SHALL return the statistics in a standardized response format with formatted currency values
7. THE Platform SHALL display the statistics on the owner dashboard page with appropriate visual cards

### Requirement 3: Mosque List Display (All Mosques)

**User Story:** As a platform owner, I want to view all registered mosques in a table, so that I can see the complete list of mosques on the platform.

#### Acceptance Criteria

1. WHEN the owner accesses the mosque list page, THE Mosque_Controller SHALL retrieve all mosques with pagination support
2. THE Mosque_Service SHALL return mosque data including: id, name, city, status, admin_user_id, created_at, congregation_count
3. THE DataTable SHALL display mosque information with columns: Name, City, Status, Admin, Members, Registration Date
4. THE DataTable SHALL support pagination with configurable items per page (default 15)
5. THE DataTable SHALL support client-side filtering by mosque status (pending, active, suspended, rejected)
6. THE DataTable SHALL support search functionality across mosque name and city fields
7. WHEN a mosque status is 'active', THE DataTable SHALL display the status with a success/green indicator
8. WHEN a mosque status is 'pending', THE DataTable SHALL display the status with a warning/yellow indicator
9. WHEN a mosque status is 'suspended', THE DataTable SHALL display the status with a danger/red indicator
10. WHEN a mosque status is 'rejected', THE DataTable SHALL display the status with a secondary/gray indicator

### Requirement 4: Pending Mosque List Display

**User Story:** As a platform owner, I want to view mosques awaiting verification in a dedicated page, so that I can quickly identify and process pending registrations.

#### Acceptance Criteria

1. WHEN the owner accesses the pending mosque page, THE Mosque_Controller SHALL retrieve only mosques with status 'pending'
2. THE Mosque_Service SHALL order pending mosques by created_at in ascending order (oldest first)
3. THE DataTable SHALL display pending mosque information with columns: Name, City, Admin Email, Phone, Registration Date, Days Waiting
4. THE DataTable SHALL calculate and display the number of days since registration for each pending mosque
5. THE DataTable SHALL support pagination with configurable items per page (default 15)
6. THE DataTable SHALL support search functionality across mosque name, city, and admin email fields
7. WHEN a pending mosque has been waiting more than 7 days, THE DataTable SHALL highlight the row with a warning indicator

### Requirement 5: Mosque Detail View

**User Story:** As a platform owner, I want to view detailed information about a specific mosque, so that I can review all mosque data before making verification decisions.

#### Acceptance Criteria

1. WHEN the owner clicks on a mosque in the list, THE Mosque_Controller SHALL retrieve the complete mosque record by ID
2. THE Mosque_Service SHALL return mosque data including: all profile fields, admin user details, congregation_count, total_donations, registration timestamp
3. THE Platform SHALL display the mosque detail page with sections: Basic Information, Contact Details, Banking Information, Location Map, Statistics
4. WHEN the mosque has a photo, THE Platform SHALL display the mosque photo
5. WHEN the mosque has latitude and longitude, THE Platform SHALL display the mosque location on an embedded map
6. THE Platform SHALL display the admin user's name, email, and phone number
7. THE Platform SHALL display congregation member count and total donation amount
8. THE Platform SHALL display the mosque status with an appropriate status badge
9. WHEN the mosque status is 'rejected', THE Platform SHALL display the rejection reason
10. WHEN the mosque status is 'active', THE Platform SHALL display the approval timestamp

### Requirement 6: Backend Data Transfer Objects

**User Story:** As a backend developer, I want to use DTOs for mosque management operations, so that I can ensure type safety and validation consistency.

#### Acceptance Criteria

1. THE Platform SHALL provide an ApproveMosqueDTO with fields: mosque_id, approved_by_user_id, approved_at
2. THE Platform SHALL provide a RejectMosqueDTO with fields: mosque_id, rejected_by_user_id, rejection_reason, rejected_at
3. THE ApproveMosqueDTO SHALL validate that mosque_id exists and refers to a mosque with 'pending' status
4. THE RejectMosqueDTO SHALL validate that rejection_reason is a non-empty string with minimum length of 10 characters
5. THE RejectMosqueDTO SHALL validate that mosque_id exists and refers to a mosque with 'pending' status

### Requirement 7: Navigation and User Interface

**User Story:** As a platform owner, I want intuitive navigation in the owner panel, so that I can efficiently access different management features.

#### Acceptance Criteria

1. THE Platform SHALL provide a sidebar navigation menu with links to: Dashboard, All Mosques, Pending Mosques, Settings
2. THE Platform SHALL highlight the active page in the sidebar navigation
3. WHEN the owner is on the dashboard, THE Platform SHALL display quick action cards linking to Pending Mosques and All Mosques
4. THE Platform SHALL display a pending mosque count badge in the sidebar if there are pending verification requests
5. THE Platform SHALL use Bootstrap 5 components for consistent styling across all owner panel pages
6. THE Platform SHALL ensure all pages are responsive and functional on desktop and tablet viewports

### Requirement 8: Performance and Data Loading

**User Story:** As a platform owner, I want fast page load times, so that I can efficiently manage the platform without delays.

#### Acceptance Criteria

1. THE Mosque_Service SHALL use database indexing on mosque status and created_at columns for optimized queries
2. THE Dashboard_Service SHALL cache platform statistics for 5 minutes to reduce database load
3. WHEN retrieving mosque lists, THE Mosque_Service SHALL use eager loading for admin user relationships to prevent N+1 query problems
4. THE DataTable SHALL use server-side pagination when the total mosque count exceeds 100 records
5. THE Platform SHALL display loading indicators while data is being fetched
6. THE Platform SHALL display appropriate empty state messages when no mosques match the filter criteria
